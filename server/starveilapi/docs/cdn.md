# CDN 与试看：能走的路和取舍

> 面向两个人的文档：改这个插件的人，和做媒体服务的人。
> 所有结论都对应到代码，改动前先读第 2 节「为什么必须服务端控制」。

## 1. 问题是什么

macCMS 的 `mac_vod.vod_play_url` 存的是**第三方直链**：

```
https://采集站A.com/vod/2026/1.m3u8
https://采集站B.com/hls/888.mp4
```

插件原本的做法是把这些地址直接下发。问题有两个：

- **付费墙形同虚设**——地址一旦给出去，抓包就能拿到全片；
- **做不了试看**——"只看前 6 分钟"没有任何一方在强制。

## 2. 为什么必须服务端控制

**前端限制一定可以被绕过。** App 里"播到 360 秒暂停"只改一个客户端；换播放器、抓包重放、改 JS 都能绕开。所以真正能挡住的只有一件事：

> **在"客户端"和"视频文件"之间放一个遵守规则的东西。**

这个"东西"可以是 CDN，也可以是自己写的媒体服务，但**必须有**。没有它，付费墙和试看都只是建议。

由此推出两条硬规则：

1. 未解锁用户**拿不到地址**，而不是"拿到了但 App 不让播"；
2. 试看地址**必须带时限**，由那个中间层执行，而不是由客户端执行。

## 3. 四条路

| 方案 | 中间层 | 能防外传 | 能按秒试看 | 成本 |
|---|---|---|---|---|
| **A. 不开 CDN**（现状默认） | 无 | ❌ | ❌ | 0 |
| **B. 普通 CDN 回源** | CDN（只校验签名有效期） | ✅ | ❌ | CDN 流量费 |
| **C. 点播 CDN（腾讯云 VOD 等）** | CDN + 点播 | ✅ | ✅ `exper` | 存储 + 流量 |
| **D. 自建媒体服务** | 自己的机器 | ✅ | ✅（自己实现） | 带宽（瓶颈） |

几条**必须知道**的事实：

- `exper`（按时长断流）**不是通用能力**。腾讯云点播、蓝汛有；阿里云、又拍、七牛的防盗链只有"链接过期"，没有"播放到 N 分钟断"。
- 腾讯云的 `exper` 也**要求 `moov` 在文件头**（faststart）+ H264。文档明写"不符合格式要求的建议转码"。
- 所以：**想按秒试看，要么用支持 `exper` 的点播服务，要么自己实现中间层。**

## 4. 自建媒体服务的两种实现

### 4.1 源是 m3u8 —— 改写播放列表（推荐）

`m3u8` 是纯文本清单：

```
#EXTINF:6.0,
seg-0001.ts
#EXTINF:6.0,
seg-0002.ts
```

媒体服务收到请求后：拉源站 playlist → 按 `#EXTINF` 累加时长 → 超过 `exper` 秒的行全部删掉 → **把剩余 `ts` 地址也改写成自己的代理地址** → 返回。

- **零存储、零转码**：只处理几 KB 文本；
- `exper` **秒级精确**（切片本身就是 6 秒一片）；
- 必须代理 `ts`，否则客户端直连源站，截断就失效了。

### 4.2 源是 mp4 —— faststart + Range

mp4 没有切片边界，只能按字节：

1. `ffmpeg -i in.mp4 -c copy -movflags +faststart out.mp4`（流拷贝，不变画质）；
2. 按码率估算 `exper` 秒对应的字节上界；
3. Range 请求超出上界 → 返回 `416`。

**这条必须"自己存一份"**：回源模式下你改不了源站的文件，而 `moov` 在文件尾部的 mp4 一旦限制前段字节，客户端连索引都读不到，直接播不了。

> 例外：如果采集站的 mp4 本来就是 faststart（很多 CDN 上传时会自动处理），可以纯回源做 Range。但**不可控**——抽查几部都是，混进一个不是的就有一部播不了。

### 4.3 两种实现的取舍

| | m3u8 截断 | mp4 Range |
|---|---|---|
| 需要存储 | ❌ | ✅（每部片 ~3GB） |
| 需要转码 | ❌ | ❌（只 faststart） |
| `exper` 精度 | 秒级精确 | 按码率估算 |
| 能纯回源 | ✅ | ⚠️ 仅 faststart 源 |

## 5. 插件在这条链路里做什么

插件**不碰任何播放流量**，只做两件事：

1. 判断谁能看（付费墙 + 会员 / 积分 / 广告解锁）；
2. 生成带签名的地址下发。

签名有两种模式（后台 `cdn_sign_type`）：

| | `tencent` | `self` |
|---|---|---|
| URL | `...?t=&exper=&rlimit=&us=&sign=` | `...?src=采集站A.com&t=&exper=&rlimit=&us=&sign=` |
| 签名串 | `md5(KEY + Dir + t + exper + rlimit + us)` | `md5(KEY + Dir + t + exper + rlimit + us + src)` |
| 用途 | 腾讯云点播 / 兼容其格式的 CDN | 自建媒体服务 |

**为什么 `self` 模式要带 `src`**：macCMS 里存的是完整直链，而 `cdn_domain + path` 会把源站域名丢掉——媒体服务收到 `/vod/1.m3u8` 不知道该去 A 站还是 B 站取，不同源站 path 还可能重名。

**为什么 `src` 必须参与签名**：否则有人把 `src` 改成任意站点，你的媒体服务就成了免费代理（SSRF）。签名是唯一能证明"这个 src 是我们发的"的东西。

**为什么 `tencent` 模式不带 `src`**：腾讯云的校验严格按它自己的签名串，多一个参数会导致签名不匹配。两种模式互斥，配置项一改就走不同分支。

## 6. 媒体服务必须实现的三件事

对接 `self` 模式时，媒体服务最少要做到：

1. **校验签名**：用同一 KEY 复算 `md5(KEY + Dir + t + exper + rlimit + us + src)`，`Dir` = 原始 path 去掉文件名；
2. **读 `exper`**：`0` = 不截断，`>0` = 截到这么多秒；
3. **按 `src` 回源**，且 `src` 只能来自**已签名参数**——绝不能信任请求头里的 `Referer`，那是可以随便写的。

参数顺序建议固定 `src, t, exper, rlimit, us, sign`（插件已按此拼），但媒体服务按名取参即可。

## 7. 一张图

```
客户端
  │  ① 请求播放地址
  ▼
插件（macCMS 那台）
  │  ② 判权限：未解锁 → 不给地址；试看 → exper=300；已解锁 → exper=0
  │  ③ 签名：md5(KEY + Dir + t + exper + rlimit + us + src)
  │  ④ 下发：https://media.example.com/{path}?src=..&t=..&exper=..&sign=..
  ▼
媒体服务（新机子）
  │  ⑤ 校验签名（同一个 KEY）
  │  ⑥ 按 src 回源
  │  ⑦ 按 exper 截断：m3u8 删行 / mp4 限 Range
  ▼
客户端播放（到点自然结束，拖不过去）
```

## 8. 上线检查清单

- [ ] 后台 `cdn_enabled` 打开、`cdn_domain` 填媒体服务域名、`cdn_sign_key` 与媒体服务一致
- [ ] `cdn_sign_type` 选对（腾讯云 → `tencent`，自建 → `self`）
- [ ] `cdn_trysee_minutes` 填了才会下发 `exper`；填 0 = 不给试看
- [ ] 媒体服务的 `Dir` 算法与插件一致（path 去掉文件名）
- [ ] 媒体服务验证过：改 `src` / 改 `exper` 都会签名不匹配
- [ ] 抽查一部片：试看能播到点停、拖不回去；解锁后能看完整、位置从断点续
- [ ] 带宽评估：自建时"出流"全在自己机器上，10Mbps 大约只够 3–4 人同时看

## 9. 另一条路：自己切片 + 逐片授权

如果愿意自己转封装（一次性 ffmpeg），可以**完全不依赖 CDN 的 `exper` 能力**，用 HLS 标准的 AES-128：

```
#EXT-X-KEY:METHOD=AES-128,URI="https://站点/key.php?vod=1&nid=3"
seg-0001.ts     ← 加密切片
seg-0002.ts     ← 加密切片
```

播放器播到每一片时，先请求 `key.php` 拿 16 字节密钥。

- **密钥接口跑在 macCMS 那台机器上**（几十行 PHP），前 N 分钟的切片给密钥，后面的直接 403；
- **视频流量不经过这台机器**；
- 任何 CDN 都能用，**不要求它支持 `exper`**。

### 为什么比点播 CDN「轻」

| | 点播 CDN（腾讯云 VOD） | 自切片 + 逐片授权 |
|---|---|---|
| 依赖厂商能力 | 要 `exper` | 只要 CDN 会分发静态文件 |
| 授权逻辑 | 由 CDN 执行 | 自己写 `key.php` |
| 换供应商 | 要重做签名与授权 | 换 CDN 不用改代码 |
| 转码 | 平台做，或自己传 | 自己做（一次性） |

### 但带宽这笔账跑不掉

**自己切片仍然要放在能扛流量的地方**——对象存储 + CDN，或者大带宽服务器。切片不会因为"自己加密"就不占流量，变的只是**不再需要 CDN 提供额外能力**：

- 点播 CDN：钱买的是「存储 + 带宽 + `exper` 能力」，绑定厂商；
- 自切片 + 授权：钱买的是「存储 + 带宽」，授权自己写，换供应商不用改代码。

### 更轻的变体：不加密，只代理改写 playlist

不想转码就走第 4.1 节的「m3u8 改写播放列表」：媒体服务拉源站 playlist → 按 `#EXTINF` 截断 → 返回。
**连存储和转码都省了**，代价是流量走媒体服务那台（或它背后的 CDN）。

### 一句话

**加密不是护城河，「密钥/切片只给前 N 分钟」才是。** 只要控制权还留在客户端（例如把完整文件加密后整段下发、由 App 解密），抓包和逆向都能绕开。

## 10. 整片加密 + 私有解码器：能防分发，不能防试看

另一个常被提出的方案：**整片加密，密钥由 `key.php` 一次下发，再自研私有解码器**，让拿到文件的人用任何公开播放器都打不开。

```
整片加密的 mp4  →  App 用私有解码器解开  →  播放
                        ↑ key.php 一次给全片密钥
```

### 它能解决什么

**防「下载后分发」。** 把容器或编码改掉之后，VLC / PotPlayer / 浏览器都打不开，文件流出去了也用不了。这一条是真的，不是心理安慰。

### 它不能解决什么

**试看。** 整片加密意味着客户端手里是**完整可解密的内容**——解密之后，全片就在内存里。「只播前 6 分钟」只是 App 里的一个 `if`：

- 改包跳过判断；
- Hook 播放进度回调，直接跳；
- Hook 解密函数，把明文 dump 出来；
- 手机录屏。

**控制权在客户端，就等于没有控制。** 这条方案做得再好，也只是把「明文直链」换成了「加密文件 + 客户端自律」，未付费用户照样能看完整片。

### 私有解码器的成本别低估

- 只是**重新编译** ffmpeg/Media3：格式还是公开的，别人照样能解，等于白做；
- **真的改格式**：要自己写 demuxer/muxer，自己处理 seek、音轨、字幕、倍速、起播缓冲；iOS 要另写一套（AVFoundation 不认你的格式）；网页版直接没有。

这不是"编译一下"的量级，是重写一个播放引擎。

### 判断标准

| 威胁 | 私有格式 + 整片加密 | 该怎么做 |
|---|---|---|
| 别人下载文件后拿去分发 | ✅ 有效 | 只有你的 App 能播 |
| 未付费用户看完整片 | ❌ 无效 | 服务端控制：不给地址 / 不给密钥 / 不给后段切片 |

两者的分界线是**内容是否完整地到了客户端**：整片加密是"到了但看不懂"，试看要的是"根本没到"。看不懂的总有办法弄懂，没到的无从下手。

## 11. 一句话结论

**不开 CDN = 全免费**（付费墙只能做到"不给地址"，做不了试看）；
**要试看 = 必须有个中间层**：买支持 `exper` 的点播服务（第 3 节 C）、自建媒体服务（第 4 节）、或自己切片 + 逐片授权（第 9 节）。
插件只负责"判权限 + 签名 + 发地址"，不承担任何流量。
